## โจทย์ (สไลด์หน้า 63)

1. หาโจทย์การแบ่งส่วน (Segmentation) วัตถุ (Object) ออกจากพื้นหลัง (Background)
2. หา Dataset อย่างน้อย 50 ภาพ และ Ground truth (ถ้าไม่มี ให้สร้างขึ้นมาเอง)
3. ออกแบบและสร้าง Algorithm เพื่อแยกวัตถุออกจากพื้นหลัง โดยกำหนดให้วัตถุที่ต้องการเป็น Positive Class และพื้นหลังเป็น Negative Class
4. ทดลองใช้ Morphology algorithm เพื่อปรับปรุงผลลัพธ์กระบวนการ Segmentation
5. วัดประสิทธิภาพการทดลอง (Evaluation) โดยให้แสดงผลลัพธ์ Confusion Matrix และ ROC Curve พร้อมทั้งอภิปรายผลลัพธ์ที่ได้
6. นำเสนออาจารย์

## สิ่งที่เลือกทำ

- **วัตถุ** ดอกทานตะวัน = Positive Class
- **พื้นหลัง** ทุกอย่างที่ไม่ใช่ดอกทานตะวัน = Negative Class
- **Dataset** PhotoArt50 คลาส `204.sunflower` เอาเฉพาะรูปถ่ายจริง 50 ภาพ
- **Ground truth** ระบายเองด้วยมือทั้ง 50 ภาพ (ดูหัวข้อ "ทำไมต้องระบายเอง")

## การตัดสินใจที่สำคัญ และเหตุผล

### ทำไมต้องระบาย ground truth เอง ทั้งที่ dataset มีให้แล้ว

PhotoArt50 มี ground truth ให้จริง แต่เป็น **กรอบสี่เหลี่ยม (bounding box)** ไม่ใช่ mask ระดับพิกเซล

```text
gt_bb/204.txt
204p_0001.jpg 55 13 202 182      <- image_name x0 y0 w h
```

โจทย์ข้อ 5 ต้องการ Confusion Matrix ซึ่งนับทีละพิกเซล จึงต้องมีเฉลยระดับพิกเซล

วัดกับภาพ `204p_0001.jpg` ได้ว่า
```text
พื้นที่ในกรอบ                       36,764 px
ดอกทานตะวันจริงที่อยู่ในกรอบ         21,219 px
พื้นหลังที่กรอบบอกผิดว่าเป็นดอกไม้    15,545 px  =  42.3% ของกรอบ
```

ถ้าใช้กรอบเป็นเฉลย เท่ากับสอนว่าพื้นหลัง 42% ในกรอบคือดอกทานตะวัน
ผลคือ algorithm ที่แยกดอกไม้ได้แม่นที่สุดจะได้คะแนนแย่ที่สุด ส่วน algorithm ที่ทายว่า
"ทั้งกรอบคือดอกไม้" จะได้คะแนนดีที่สุด ซึ่งกลับหัวกับสิ่งที่โจทย์ต้องการวัด

โจทย์ข้อ 2 เขียนไว้แล้วว่า *"ถ้าไม่มี ให้สร้างขึ้นมาเอง"* จึงระบายเอง

### ทำไมไม่ให้โปรแกรมเดา ground truth ให้ก่อนแล้วค่อยแก้ด้วยมือ

สิ่งที่เรากำลังจะวัด คือความแม่นของการตัดค่าสี
ถ้าเอาการตัดค่าสีมาสร้างเฉลยเสียเอง ก็คือเอาคำตอบไปเป็นเฉลยของตัวเอง วัดแล้วไม่มีความหมาย

### ทำไมใช้ Lab ช่อง b ไม่ใช่ HSV

โจทย์ข้อ 5 ต้องการ ROC Curve ซึ่งสไลด์หน้า 59 นิยามว่าเป็นผลของ classifier
**at varying threshold values** คือต้องกวาดค่าตัด "ค่าเดียว"

`cv2.inRange` บน HSV ต้องกำหนดตัวเลข 6 ตัว (ขอบล่าง-ขอบบนของ H S V) กวาดไม่ได้
จึงต้องบีบภาพให้เหลือคะแนนตัวเดียวต่อพิกเซลก่อน

Lab แยกสีเป็น L = ความสว่าง, a = เขียว↔แดง, **b = น้ำเงิน↔เหลือง**
ช่อง b วัดความเหลืองตรงๆ วัดกับภาพจริงได้

| ภาพ | พื้นหลัง | b ในดอก | b พื้นหลัง | ห่างกัน |
|---|---|---|---|---|
| 0001 | ดำ | 193 | 131 | 61 |
| 0020 | ฟ้า | 178 | 114 | 64 |
| 0009 | ใบไม้เขียว | 183 | 142 | 40 |
| 0033 | เทา | 189 | 146 | 43 |
| 0043 | เทาซีด | 181 | 133 | 48 |

ลองช่อง Hue เทียบแล้วแย่กว่ามาก เพราะ Hue คือ "มุมของสี" พิกเซลสีเทา ดำ ขาว ไม่มีสี
จึงไม่มีมุมสีที่มีความหมาย ค่าที่ได้กระโดดมั่ว ในขณะที่พื้นหลังของ dataset นี้มีทั้งดำ เทา และขาว

### ทำไมลำดับ morphology ต้องเป็น Opening → Closing → Region Filling

| ขั้น | แก้ปัญหาอะไร | สไลด์ |
|---|---|---|
| Opening | จุดขาวเล็กๆ ในพื้นหลัง จากใบไม้หรือดอกอื่นที่บังเอิญเหลืองพอ | หน้า 24 |
| Closing | วงกลีบดอกขาดเป็นตัว C เพราะกลีบบางกลีบสีเข้มไป | หน้า 24 |
| Region Filling | เกสรกลางดอกเป็นรูดำ ทำให้ mask เป็นวงโดนัท | หน้า 34-35 |

สลับลำดับไม่ได้ เพราะ Region Filling อุดได้เฉพาะรูที่ถูกล้อมรอบมิดชิด
ถ้าวงกลีบยังขาด รูตรงกลางจะทะลุออกนอกภาพ ไม่นับเป็นรู

พิสูจน์กับ `204p_0020.jpg`
```text
ไม่มี Closing ก่อน   13,633 -> 13,666 px   อุดไม่ได้เลย
มี Closing ก่อน      19.6% -> 27.1%        อุดได้
```

### ทำไมไม่ใช้ Closing อุดรูเกสร ทั้งที่สไลด์บอกว่า Closing "fills holes"

สไลด์หน้า 24 เขียนครบว่า *"fills holes **smaller than the structuring element**"*
เกสรกลางดอกใหญ่กว่า SE มาก

วัดกับ `204p_0001.jpg` ด้วย SE 15x15
```text
20,052 -> 21,318 px   เพิ่มแค่ 6%   รูยังโหว่อยู่
```

จะอุดได้ต้องใช้ SE ใหญ่กว่ารู ซึ่ง SE ขนาดนั้นจะไปกลืนพื้นหลังพังหมด
ครูเขียนกำกับไว้ในสไลด์หน้า 35 แล้วว่า Region filling ของ Python ให้ตามไปอ่านลิงก์นี้แทน
เพราะ OpenCV ไม่มี operation นี้ให้เลือกใช้
https://learnopencv.com/filling-holes-in-an-image-using-opencv-python-c/
